# 项目文件组成与功能

本文按「真实仓库里有什么」说明，不是理想中的目标架构。设计文档 `01_System_Architecture.md` 里部分目录（例如 `backend/app/api/`）尚未拆分，以本文为准。

## 1. 总览（树状图）

```
RxWeb/
├── README.md                 项目简介，并指向本文档
├── start.ps1                 Windows 一键启动（生产方式，8001）
├── start-dev.ps1             Windows 本机热更新（浏览器打开 8001）
├── start.sh                  Ubuntu / 宝塔一键启动
├── .gitattributes            保证 .sh 使用 Linux 换行符
├── .gitignore                Git 不提交 venv、node_modules、zip、口令
├── deploy/                   发布脚本和各网站的调试机/生产机配置
│   ├── deploy.ps1            Windows 发布到指定站点
│   ├── deploy.sh             Linux 发布到指定站点
│   ├── pack-deploy.ps1       打 RxWeb-deploy.zip
│   └── sites/                每个网站一份 site.env（目录、端口分开）
├── company.db                SQLite 数据库（没有则启动脚本会生成）
├── requirements.txt          历史遗留的 Flask 清单，当前后端不用它
│
├── backend/                  Python 后端
│   ├── requirements.txt      真正要安装的依赖（FastAPI、uvicorn 等）
│   ├── seed.py               写入演示产品 / 新闻 / 下载
│   └── app/
│       ├── __init__.py       让 app 成为可导入的包
│       └── main.py           全部 API + 生产环境托管前端 dist
│
├── frontend/                 Vue 前端
│   ├── package.json          前端依赖与 npm 脚本
│   ├── package-lock.json     锁定依赖版本
│   ├── vite.config.js        Vite 开发服务器 / 打包配置
│   ├── index.html            前端 HTML 入口
│   ├── src/                  页面与组件源码
│   └── dist/                 构建产物（部署必需，一般不提交 Git）
│
└── docs/                     说明与设计文档
```

下面按目录解释「它负责什么、新手会不会碰到」。

## 2. 根目录：启动与部署

| 文件 | 功能 | 新手何时用 |
|------|------|------------|
| `start.ps1` | Windows 下创建 `.venv`、装依赖、构建前端、启动 8001 | 本机按调试机方式预览 |
| `start-dev.ps1` | Windows 热更新，浏览器打开 8001 | 改 Vue / API 立刻刷新 |
| `start.sh` | Ubuntu 下同样流程；`--daemon` 可后台跑 | 云服务器测试主机运行 |
| `deploy/deploy.ps1` | 按站点发布到调试机或生产机。生产地址或端口为空时拒绝发布 | 更新云服务器 |
| `deploy/sites/<站点>/site.env` | 该网站在调试机、生产机上的目录和端口 | 新增一家公司时复制一份 |
| `deploy/pack-deploy.ps1` | 生成本地 `deploy/RxWeb-deploy.zip`（不含 Windows 的 venv） | 手动上传 Ubuntu 前 |
| `company.db` | 网站数据文件 | 启动脚本会自动创建；备份网站主要就是备份它 |

**不要上传 / 不要提交：**

- `backend/venv/`：Windows 虚拟环境，Linux 无法运行
- `frontend/node_modules/`：体积大，应在对应系统重新 `npm install`
- `.venv/`：各系统自己生成
- `RxWeb-deploy.zip`：打包产物

## 3. 后端 `backend/`

当前后端很集中：**几乎所有接口都在 `app/main.py`**。

| 文件 | 功能 |
|------|------|
| `requirements.txt` | `pip install -r` 会装 FastAPI、uvicorn、pydantic 等 |
| `seed.py` | 创建 `products` / `news` / `downloads` 表并插入演示数据。注意它会 `DROP` 产品表和新闻表再重建，**不要对已有真实数据随便执行** |
| `app/main.py` | 定义 FastAPI 应用：CORS、读 SQLite、`/api/news`、`/api/products`、新闻增删改；若存在 `frontend/dist` 则同时提供官网页面 |
| `app/__init__.py` | 空包标识，保证 `uvicorn app.main:app` 能导入 |

数据库路径默认是项目根目录的 `company.db`。每个网站部署在自己的目录里，因此各有一份数据库。也可用环境变量 `RXWEB_DB` 改路径。

根目录那个 `requirements.txt` 写的是 Flask，**和现在的 FastAPI 项目无关**，不要拿它去 `pip install`。

## 4. 前端 `frontend/`

| 文件 / 目录 | 功能 |
|-------------|------|
| `package.json` | `npm run dev` 开发调试；`npm run build` 生成 `dist` |
| `vite.config.js` | 开发时把 `/api` 代理到别的端口（部署后由 FastAPI 同源提供 `/api`，不再走这层代理） |
| `index.html` | 浏览器入口，里面挂载 `#app` |
| `src/main.js` | 创建 Vue 应用，接入路由、Pinia、Element Plus |
| `src/App.vue` | 整站外壳：顶栏 + 内容区 + 页脚 |
| `src/router/index.js` | 网址和页面的对应关系（`/` 首页、`/products` 产品等） |
| `src/views/` | 各个页面：Home、ProductList、News、Downloads、Contact、Login、Admin 等 |
| `src/components/` | 顶栏 `TheHeader`、页脚 `TheFooter` |
| `src/services/` | 请求封装。新闻走真实 `/api/news`；产品服务里仍有一份本地 mock，列表页可能同时用到接口与 mock，以页面代码为准 |
| `dist/` | **部署用的编译结果**。没有它，8001 端口只能当纯 API |

开发模式：`start-dev.ps1` 或 `cd frontend && npm run dev`，浏览器打开 **8001**。瑞学调试机也是这个端口，页面和接口在一起。生产地址和端口以后再填。

## 6. 运行时生成、通常不入库的文件

| 路径 | 谁创建 | 作用 |
|------|--------|------|
| `.venv/` | 启动脚本 | Linux/本机新虚拟环境 |
| `frontend/node_modules/` | `npm install` | 前端依赖 |
| `frontend/dist/` | `npm run build` | 生产页面 |
| `logs/rxweb.log` | `--daemon` | 后台日志 |
| `rxweb.pid` | `--daemon` | 后台进程号 |
| `rxweb-dev-backend.pid` | `start-dev.ps1` | 本机开发后端进程号 |

把这些和源码区分开：源码要备份；这些可以在新机器上重新生成。
