# 开发与测试问题与经验汇总

## 1. 目录与命令执行错误
- 未切换到正确的子目录（如 frontend/backend）就执行 npm/yarn/cypress/python 命令，导致找不到 package.json、依赖或 app 包，服务或测试无法启动。
- 在项目根目录下运行前端/后端相关命令，导致服务或测试无法启动。
- 建议：每次执行命令前，先 pwd/cd 明确当前目录，前端命令只在 frontend，后端命令只在 backend/app（或 backend）。

## 2. 端口与服务相关错误
- 启动服务时端口被占用，未能及时切换或释放端口，导致服务无法正常启动。
- Vite 启动时端口被占用，自动切换端口导致 Cypress 无法连接。
- 启动服务未加 --host，导致 Cypress 或其他进程无法访问本地服务。
- 启动服务未加 --strictPort，导致端口漂移。
- 建议：前后端端口需统一，遇到端口占用优先切换端口并同步修改配置，启动服务加 --host --strictPort。

## 3. 服务启动顺序与状态检查
- Cypress 测试时服务器未启动或未就绪，导致 ECONNREFUSED。
- 手动后台启动服务器不稳定，进程管理混乱。
- 建议：用 start-server-and-test 工具自动串联服务与测试，或手动 curl 检查服务状态。

## 4. 路由与页面挂载错误
- 路由未正确指向新开发页面，导致页面内容与预期不符。
- 测试用例访问了未挂载的页面，导致 404 或内容不符。
- 建议：先配路由再写内容，开发一小步测试一小步，保证路由和页面同步。

## 5. 自动化测试用例设计与执行错误
- 测试断言与页面实际内容不符，未考虑异步加载或分页，导致偶发性断言失败。
- 测试用例未等待接口返回和页面刷新，导致断言失败。
- 未处理良性前端异常（如 ResizeObserver loop），导致 Cypress 测试误报失败。
- 建议：测试用例应与页面实际展示内容严格对应，断言前加等待，处理良性异常。

## 6. 工具链与脚本参数错误
- start-server-and-test 参数拼接错误，导致测试命令无法执行。
- npm run test:e2e -- --spec ... 语法错误，参数未正确传递到底层工具。
- 依赖脚本未封装专用命令，导致手动拼接参数易出错。
- 建议：用 package.json 封装专用测试命令，参数传递规范。

## 7. 依赖管理混乱
- vite、start-server-and-test 被错误地加入生产依赖。
- 自动化脚本误操作导致依赖分类错误。
- 建议：手动修正 package.json，将开发依赖归类到 devDependencies。

## 8. 网络监听与本地连接问题
- 服务器已启动但 Cypress 依然无法连接。
- Vite 默认只监听 localhost，某些环境下 Cypress 进程无法访问。
- 建议：启动 Vite 时加 --host，监听所有网络接口。

## 9. 数据依赖与测试数据问题
- Cypress 测试找不到页面元素，实际是后端无数据或接口未通。
- 未保证数据库有种子数据，或前端异步加载未完成。
- 建议：测试前先 curl 验证 API 数据，必要时写入种子数据，测试用例中加数据加载断言。

## 10. 经验教训与流程改进
- 自动化测试环境要保证端口、进程、依赖、网络监听等配置高度一致。
- 推荐使用 start-server-and-test 工具管理测试流程，避免手动操作带来的不确定性。
- 测试脚本应对常见良性警告做兼容处理。
- 依赖管理要定期检查，防止开发依赖进入生产环境。
- 实施前置检查清单，开发、测试、集成前先自查目录、端口、依赖、服务状态。
- 采用集成优先、测试驱动开发模式，开发一小步测试一小步，保证代码和测试始终同步。
- 建立标准化测试模板，封装异常处理和专用测试脚本。
- 持续集成开发、测试、修正，确保每一步都可回溯和复盘。

---

> **自查建议**：每次开发、测试、联调前，先明确当前目录、端口、代理和服务状态，curl 验证 API，最后再跑自动化测试。反复出错的地方要写进自查清单和团队文档，持续复盘。
