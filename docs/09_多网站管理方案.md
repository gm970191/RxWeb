# 多网站管理方案

已按本文执行：本机接口端口与 `start-dev.ps1` 对齐，本机数据库为 `data/<站点名>/company.db`，益如驰已发布到调试机 8010。生产地址仍为空。

同一套程序服务多家公司。公司之间的名称、联系方式、产品和新闻只放在各自的站点目录里。发布某一家时，服务器上只出现这一家的数据。

## 1. 18001 是什么

**18001 不是任何一家公司的网站端口。** 调试机和生产机都不监听它。

它只在 Windows 本机改页面时出现。这时要同时开两个程序：

| 程序 | 本机端口 | 作用 |
|------|----------|------|
| Vite | 8001 | 浏览器打开的地址。改 Vue 源码会立刻刷新 |
| FastAPI | 18001 | 只给本机 Vite 转发 `/api`。浏览器不直接访问 |

页面请求 `/api/news` 时，Vite 把请求转到 `http://127.0.0.1:18001`。如果接口也占用 8001，就和 Vite 抢同一个端口，热更新起不来。

正式运行和调试机都是另一种方式：先构建 `frontend/dist`，再由一个 Python 进程同时提供页面和 `/api`。端口只来自该站点的 `site.env`。

| 站点 | 调试机端口 | 目录 |
|------|------------|------|
| 瑞学 `ruixue` | 8001 | `/www/wwwroot/RxWeb8001` |
| 艾尔德 `aierde` | 8009 | `/www/wwwroot/aierde8009` |
| 益如驰 `yiruchi` | 8010 | `/www/wwwroot/yiruchi8010` |

18001 目前写在两处，而且没有连在一起：

- `start-dev.ps1` 的 `-BackendPort`，默认 18001
- `frontend/vite.config.js` 里写死的代理地址 `http://127.0.0.1:18001`

只改脚本参数时，Vite 仍会把接口转到 18001。确认本方案后，代理改为读取同一个环境变量，并在 `start-dev.ps1` 的说明里写明：这是本机开发端口，不是网站端口。

## 2. 文件怎么分

程序只有一份。每加一家公司，只加一个站点目录，不复制后端和前端源码。

```
RxWeb/
├── backend/                  各站共用。seed.py 不含任何公司的产品或新闻
├── frontend/src/             各站共用。页面从 site-profile 读取当前站点
├── start.ps1 / start.sh      各站共用的启动程序
├── start-dev.ps1             仅本机热更新，使用 8001 + 18001
└── deploy/
    ├── deploy.ps1            发布时必须指定 -Site
    ├── machines.env          调试机 SSH 口令，不提交
    └── sites/
        ├── ruixue/
        ├── aierde/
        └── yiruchi/
```

每个站点目录里只有这一家的文件：

| 文件 | 内容 | 谁会拿到 |
|------|------|----------|
| `site.env` | 调试机、生产机的地址、目录、端口 | 只在发布脚本里读，不上传到网站目录 |
| `profile.js` | 页头、页脚、首页文案、联系方式、下载页条目 | 只打进这一家的前端包 |
| `seed_data.py` | 产品、新闻、留言、演示账号邮箱 | 发布时复制成该站的 `backend/site_seed.py` |
| `runtime.env.example` | 端口和发信配置示例 | 真实 `runtime.env` 不提交 |

服务器上每个网站是一份独立目录，里面有自己的程序副本、`company.db` 和 `runtime.env`。目录之间不共享数据库。

本机仓库根目录现在只有一个 `company.db`。用 `start.ps1 -Site` 切换公司时会写进同一个文件。确认后改为：

```
data/<站点名>/company.db
```

该目录不提交。调试机上的数据库仍在各自网站目录里，不放进 `data/`。

## 3. 新增一家公司时做什么

1. 新建 `deploy/sites/<站点名>/`，站点名只用小写字母、数字和连字符。
2. 写 `site.env`。调试机端口在全机范围内不能重复。生产地址留空，未明确指示前不执行 `-Target prod`。
3. 写 `profile.js` 和 `seed_data.py`。文件第一处标明本站 `site` / `SITE_ID`，发布脚本会核对，对不上就停止。
4. 本机需要看效果时：`start.ps1 -Site <站点名>`，数据进 `data/<站点名>/company.db`。
5. 发布调试机：`pwsh -File .\deploy\deploy.ps1 -Site <站点名>`。第一次需要演示数据时再加 `-Reseed`。`-Reseed` 会重写该站数据库里的产品和账号。

发布包里有：`start.sh`、`backend/`（含这一家的 `site_seed.py`）、`frontend/dist/`、按该站生成的 `runtime.env`。没有其他公司的 `profile.js` 或 `seed_data.py`。

`start.sh` 在仓库里用占位符 `@RXWEB_APP_PORT@`。打包和发布时把它换成该站 `site.env` 的端口，并写入 `runtime.env` 的 `PORT`。门户启停即使带入了别的站的 `PORT`，也会改用本站端口。本机 `start.ps1 -Site <站点名>` 不写 `-Port` 时，用的是同一份 `DEBUG_APP_PORT`。
