# 打包方法

「打包」= 整理出一份**能在目标机器上跑起来**的文件，去掉对方用不到、甚至会害对方的东西（例如 Windows 的 `venv`）。

## 1. 先分清两种包

| 包的形态 | 里面有什么 | 用在哪 |
|----------|------------|--------|
| 源码目录 / Git | 全部源码 + 脚本 + 文档 | 开发、继续改代码 |
| `deploy/RxWeb-deploy.zip` | 后端 + 启动脚本 +（最好带上）`frontend/dist` | 上传 Ubuntu / 宝塔 |

新手传到阿里云，用 **zip**，或直接用 `deploy/deploy.ps1` 按站点发布。同一份程序发到不同目录和端口，网站数据仍各用各的 `company.db`。

## 2. 必须打进去 vs 绝对不要打进去

**建议打进 zip：**

- `start.sh`、`start.ps1`（服务器只用 sh）
- `backend/app/`、`backend/requirements.txt`、`backend/seed.py`
- `frontend/dist/`（本机构建成功的话）
- 若没有 dist：再带上 `frontend/src`、`package.json`、`package-lock.json`、`vite.config.js`、`index.html`（服务器必须装 Node）
- 可选：`company.db`（已有真实数据时）

**不要打进去：**

- `backend/venv/`、`.venv/`
- `frontend/node_modules/`
- `.git/`、`docs/`（服务器运行不需要）
- `frontend/cypress*`（测试）

## 3. 方法 A：Windows 一键打 zip（推荐）

在项目根目录打开 PowerShell：

```powershell
cd D:\Projects\RxWeb
pwsh -File .\deploy\pack-deploy.ps1
```

脚本会：

1. 若本机有 `npm`，先执行 `npm run build`，zip 里带 `frontend/dist`（服务器可以不装 Node）
2. 若没有 npm，则打包前端源码（服务器必须装 Node 才能构建）
3. 生成 `D:\Projects\RxWeb\deploy\RxWeb-deploy.zip`

把这个 zip 用宝塔「文件」上传到服务器，例如放到 `/www/wwwroot/RxWeb-deploy.zip`。

**注意路径：** zip 在哪，解压命令就指向哪。不要照抄 `/tmp/`，除非你真的传到了 `/tmp/`。

## 4. 方法 B：手动复制（理解原理用）

新建空文件夹，只拷第 2 节「建议打进 zip」那些路径，用资源管理器或 7-Zip 压缩。效果和脚本类似，但容易漏文件或误带 `venv`。

## 5. 解压到 Ubuntu 的正确命令

假设 zip 已经在 `/www/wwwroot/RxWeb-deploy.zip`：

```bash
apt install -y unzip
mkdir -p /www/wwwroot/RxWeb
unzip -o /www/wwwroot/RxWeb-deploy.zip -d /www/wwwroot/RxWeb
ls /www/wwwroot/RxWeb
# 应能看到 start.sh 和 backend
sed -i 's/\r$//' /www/wwwroot/RxWeb/start.sh
```

`unzip -d` 的意思是「解压到这个目录」。目录不存在时，`unzip` 一般会创建它。

若 `ls` 看到的是套了一层多余的 `RxWeb` 或文件全在 zip 根目录，以实际 `ls` 为准，保证 **最终** 路径是 `/www/wwwroot/RxWeb/start.sh`。

## 6. 更新网站时怎么再打包

改完前端或后端后：

1. Windows 再跑一次 `deploy/pack-deploy.ps1`
2. 上传新 zip，在服务器上再次 `unzip -o ...`（`-o` 覆盖旧文件）
3. `bash /www/wwwroot/RxWeb/start.sh --stop`
4. `bash /www/wwwroot/RxWeb/start.sh --daemon`

不要覆盖正在使用的 `company.db`，除非你确定要换成打包进去的那份数据库。可以先把服务器上的 `company.db` 复制到旁边备份。
